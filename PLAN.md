# Cupcake plan: one app, one address

Status: adopted Oct 18, 2026. Source analysis: the two-app comparison below.

## Decision

- **`notsoround/hales-ai-website` is the single source of truth for the Cupcake app.** `https://hales.ai/cupcake` is the only public Cupcake address.
- **`cupcake-opolis` is the agent/Gateway only.** Its Control UI stays private on the tailnet as the admin console: chat, channels, scheduled jobs, device pairing, and coding/agent access.
- All seven ports below ship as **one consolidation PR** on hales-ai-website. Nothing deploys to hales.ai/cupcake until Matt reviews and approves it.

## Seven features to port into hales.ai/cupcake

1. Glucose readings from the library (`glucose_manual_list`).
2. Server-side exercise storage: an owner-only exercise log in the Cupcake library.
3. Café/takeout purchases from bank alerts, shown as **bought markers only**. Context, not consumption.
4. Calm/Hot accent toggle.
5. 6 PM sugar card.
6. Metabolic balance curve, rebuilt on the original app's calorie math (`nutritionModel.ts`).
7. Quick-log exercise button.

## Must survive untouched

The Vapi phone line and call outcomes, Wins & losses, receipts, and the Today / Talk / Record / Library / Chat tab bar. Also unlock, the Today shortcuts (FOOD TODAY, Food photo, Quick tip, Record a note), and every existing real data path (library, n8n webhooks).

## URL strategy

- `https://hales.ai/cupcake`: the only public Cupcake address.
- `cupcake.hales.ai`: retire it as a public address. Old bookmarks redirect to `https://hales.ai/cupcake`.
- The Control UI stays reachable privately on the tailnet (`cupcake-brain-01` via Tailscale serve) as the admin console.
- Never redirect `hales.ai/cupcake` anywhere else.

## Decisions Matt confirmed (Oct 18, 2026)

1. Retire public `cupcake.hales.ai`; bookmarks redirect to `hales.ai/cupcake`. The Control UI stays tailnet-only as the admin console.
2. An owner-only exercise log in the Cupcake library is fine.
3. Only logged meals count as eaten on the metabolic curve. Purchases are context, not consumption.

## 3. What the OpenClaw Control UI provides that hales-ai-website can't easily replace

These are the Gateway's admin and operator surfaces. They're unrelated to the Cupcake _app_, but they're the only way to run the agent:

- **Agent chat with full tool use, sessions and session history** (`/chat`, `/sessions`, `/new`): the Cupcake agent runtime (models, skills, memory) on brain-01. hales' Quick chat goes through the library, which is a different and narrower path.
- **Channels** (`/settings/channels`): Telegram (primary), WhatsApp, Discord, Slack connections and pairing.
- **Automations / cron** (`/automations`): the Cupcake heartbeat and metrics jobs, plus any scheduled agent work.
- **Memory and Memory Dreaming** (`/settings/memory`, dreaming), **Agents**, **Skills**, **Plugins** (where `cupcake-nutrition` and others are enabled), **MCP**, **model providers / setup**.
- **Config, secrets, approvals, security, device / node pairing** (`/settings/devices`), logs, usage, debug, workboard, terminal.

Rebuilding any of this in the website isn't realistic. **Decision implication:** the Control UI should stay reachable as an **admin console**, but it doesn't need to be a public "Cupcake app" address.

## 4. Migration plan

**Source of truth for the Cupcake app: `notsoround/hales-ai-website`** (`src/pages/cupcake/sandbox/cupcakegpt/page.tsx` + `src/components/cupcake/`).
**Source of truth for backend services:** the library, recordings and health connector stay where they are on hales. `vapi-call-context` stays in cupcake-opolis for now (it ships from there and is already live); optionally move it later to a small repo of its own (§ risks). `cupcake-opolis` = agent/Gateway only.

### Ordered steps (data connections first; shipped together as ONE consolidation PR on hales-ai-website; no new deps)

1. **Freeze the Cupcake UI in opolis.** No further Today/nutrition features there. Optionally disable `cupcake-nutrition` later, once nothing reads it (it's read-only, so no data risk).
2. **Glucose read (data).** Add a `glucoseApi.ts` calling Library `glucose_manual_list` (pattern: `weightApi.ts`). Library-only, no n8n.
3. **Exercise store (data, needs a backend change).** Add library actions `exercise_log` / `exercise_list` / `exercise_delete` (owner-only, append-only like `personal_outcomes`), _or_ decide to store exercise as Cupcake Live check-in metrics. Without this, exercise stays per-browser as in opolis. **This is the only server-side change in the plan.**
4. **Prepared-food purchases (data).** For the curve's "bought" term: prefer the transaction items already in `cupcake-feed`, classified client-side with the `PREPARED` regex from opolis `extensions/cupcake-nutrition/src/sources.ts`. Fallback: a library action proxying the brain webhook `recent_bank_events`. Avoid adding a new browser-to-n8n dependency if the feed suffices.
5. **Theme tokens + Calm/Hot toggle (UI).** Turn the hard-coded pinks in `studio.css` into `--cc-pink*` variables; add a `data-accent-heat` attribute and a toggle in the top bar (port `accent-heat.ts` logic; localStorage key).
6. **6 PM sugar card on Today (UI).** Uses step 2.
7. **Metabolic balance curve on Today / Food (UI).** Port `metabolic-series.ts` (+ its tests to plain TS checks); React SVG component; inputs: meals (existing `nutritionApi.ts`), expenditure (existing `food_settings`), purchases (step 4), exercise (step 3), steps = none until a real source exists. Reuse `nutritionModel.ts` for prorating so there's one energy model.
8. **Quick-log exercise button (UI).** Port `exercise-estimate.ts` + `speech-dictation.ts`; React button/dialog; writes via step 3.
9. **Deploy** the consolidation PR, after Matt reviews and approves it, through `ops/deploy-prebuilt-hales-ai.sh` (reviewed page SHA, Cupcake lint/typecheck/build gate, `--apply` only after review; automatic rollback image).
10. **URL cut-over** (below), then remove the Cupcake-branded Today from opolis main or leave it unlinked.

### URL strategy

- **`https://hales.ai/cupcake`** is the only Cupcake address (PWA scope `/cupcake` already matches). Keep it as is; it's live and returning 200 today.
- **`cupcake.hales.ai`**: recommended **retire the public vhost and keep the Control UI tailnet-only** at `https://cupcake-brain-01.<tailnet>.ts.net` as the admin console. Optionally make public `cupcake.hales.ai` a 302 to `https://hales.ai/cupcake`, so old bookmarks and the rebrand (#8) land in the right app.
- Don't reintroduce the `/cupcake` → `cupcake.hales.ai` redirect. Last night's version of it is exactly what hid the app from Matt.

### Risks

- **n8n dependencies stay load-bearing**: `cupcake-feed` (Today signals, Wins & losses), `cupcake-intervention-update`, `cupcake-voice-session` / `-voice-end` (Talk), `cupcake-recording-*` (Record, nginx-routed to the recordings service). Consolidating the UI doesn't reduce this. Don't touch those workflows during migration.
- **Phone line**: Vapi → `cupcake-vapi-call-context` (hales) + n8n routers. It's independent of either UI, but its **source lives in cupcake-opolis**. If opolis is ever pruned back to stock OpenClaw, move `extensions/vapi-call-context` out first, or keep it pinned there. The URL decision must not touch Vapi server URLs.
- **Auth model difference**: hales uses one owner password over `X-Cupcake-Key` from the browser. Every ported write (exercise) must stay owner-only on the library side.
- **Deploy is Mac-bound**: prebuilt deploy builds on Matt's Mac with a reviewed page hash. Agents can prepare PRs but can't complete a release unattended.
- **Two energy models**: porting the curve must reuse hales' `nutritionModel.ts` rules (incomplete-history guard, effective-dated settings). Otherwise the curve and the balance number will disagree.
- **Repo lint debt**: hales' whole-repo lint has six pre-existing errors in non-Cupcake files. The deploy gate checks the Cupcake directory only.
